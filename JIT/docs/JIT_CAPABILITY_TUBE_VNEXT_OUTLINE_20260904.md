# Part I — What JIT is actually trying to do

## 1. The research object

JIT should no longer be described as merely training a better jumping policy.

The project separates four layers:

### 1.1 Physical/task feasibility `F*`

`F*` is the conceptual set of physical states from which **some admissible control behavior** could complete the fixed jumping task under the fixed XML, actuator limits, contact geometry and task semantics.

JIT does not compute or prove `F*` exactly.

### 1.2 Cumulative empirical capability evidence `E_k`

`E_k` is evidence accumulated from successful real-dynamics rollouts generated by:

- bootstrap phase experts;
- selected/frozen unified policies;
- policy-conditioned frontier probes.

A later policy failing from an earlier successful state does not erase the historical fact that successful control was previously demonstrated there.

### 1.3 Resolution-aware capability Tube `T_k`

`T_k` is a sparse physical-state representation of empirical support.

It answers:

> At this physical resolution, which regions of the jumping state space have we actually occupied with evidence/support?

It is derived from replayable snapshots but is not identical to the raw snapshot list.

### 1.4 Single-policy realization `R(pi_k, T_k)`

The final deployment target remains one unified Actor.

Therefore the project also asks:

> How much of the cumulative capability support can this particular Actor realize consistently?

This is a separate question from whether the state/behavior is physically achievable at all.

---

## 2. Why the mainline remains target-free

The current policy is not given an explicit target such as:

```text
desired jump distance
desired apex height
desired landing point
```

The user explicitly decided **not** to add such intent in the current revision.

The reason is structural:

JIT is currently trying to expose a **state-space Tube**, not a single desired trajectory family.

At one longitudinal position `x`, the robot may have multiple successful continuation states:

```text
same x
+ different z
+ different vx/vz
+ different pitch/pitch-rate
+ different joint posture
```

All of these can be meaningful members of the Tube.

Introducing a fixed goal now would require reward/observation redesign and may push optimization toward a narrower goal-conditioned behavior family. That is scientifically legitimate, but it is a different method version.

Therefore current vNext explicitly preserves:

```text
reward semantics unchanged
Actor observation unchanged
success semantics unchanged
target-free task unchanged
```

Goal-conditioned JIT remains a later option only if the reconstructed Tube demonstrates a real multimodal/branching policy-representation problem.

# Part IV — Why the physical resolution revision is necessary

## 15. Problem with raw snapshot cardinality

Suppose two snapshots differ numerically:

```text
A: x=1.213, z=.842, vx=2.36, pitch=3.18 deg
B: x=1.217, z=.845, vx=2.39, pitch=3.24 deg
```

Their state SHA values differ.

However under the vNext resolution:

```text
x      0.10 m
z      0.10 m
vx     0.10 m/s
pitch  0.50 deg
```

these may map to the same capability cell.

They remain two exact replay snapshots, but they should not count as two independent macroscopic expansion regions.

---

## 16. Actor observation is not the capability space

Current Actor inputs include controller-specific/history information such as:

- FIFO frames;
- gravity vector;
- angular velocity;
- acceleration;
- joints;
- wheel velocity;
- last action;
- obstacle-relative x/root height;
- history validity;
- jump signal.

A direct distance in this observation vector would mix:

```text
physical state
sensor representation
controller memory
previous action
```

Therefore vNext projects directly from physical snapshot `qpos/qvel` into a capability coordinate space.

# Part V — Capability coordinate schema v1

## 17. Root geometry cell

Primary macroscopic Tube geometry:

```text
phase
root x/y/z
root vx/vy/vz
roll/pitch/yaw
root wx/wy/wz
```

This profile answers:

> Is the robot occupying a meaningfully different body-state region in the jump?

It is the preferred metric for:

- Tube shape;
- x-slice cross-section;
- frontier parent diversity;
- macroscopic expansion count.

---

## 18. Full physical cell

Adds:

```text
steering angle/rate
hip angle/rate
knee angle/rate
front/rear wheel tangential speed
```

It answers:

> Even when body trajectory geometry is similar, did we gain meaningful internal configuration diversity?

Wheel rotational phase is intentionally not used as a cell coordinate because two wheel angles separated by rotation phase should not automatically be treated as distinct capability regions. Wheel tangential speed is used instead.

---

| Coordinate family | Resolution |

| root x/y/z | 0.10 m |

# Part VI — What a physical Tube should look like

## 20. Longitudinal progress coordinate

Use root `x` as the first progress coordinate.

Resolution:

```text
Delta x = 0.10 m
```

This produces slices:

```text
x = ... 1.0, 1.1, 1.2, 1.3 ... m
```

Within each slice, the Tube has a cross-section over the remaining physical coordinates.

---

## 21. Cross-section

Primary cross-section quantities:

```text
y, z
vx, vy, vz
roll, pitch, yaw
wx, wy, wz
```

For every x slice, vNext records:

```text
unique occupied root cells
raw snapshot density
phase counts
min
q25
median
q75
max
```

This makes the Tube inspectable as a spatial/dynamical structure.

---

## 22. Tube shape is data, not a rendering constraint

The project does not require a mathematically circular cylinder.

Observed geometry may be:

```text
wide band
narrow bottleneck
branch
multiple disconnected lobes
gap
```

These shapes are scientifically meaningful.

In particular, multiple upstream lobes may help explain why pi_2 gained frontier capability while losing old upstream realization: one Actor may have shifted toward a different successful behavior branch.

This is currently a hypothesis to test with geometry, not a conclusion.

Only after this geometric evidence should intent/latent behavior conditioning be reconsidered.

This is important local frontier-learning evidence even though pi_2 loses substantial upstream source-panel coverage.

# Part XIV — Revised JIT story

## 49. Short scientific story

> JIT is a target-free, real-dynamics capability discovery loop that uses frozen policies as probes, identifies the current success/failure frontier, converts newly supported regions into just-in-time replay curriculum, and iteratively maps a resolution-aware jumping capability Tube while separately measuring how much of that accumulated Tube a single deployable policy can realize.

## 50. What makes the story different from ordinary RL

Ordinary RL usually reports:

```text
return
success rate
```

JIT additionally asks:

```text
Where in physical state space is success supported?
Where is the current frontier?
Which physical cells are genuinely new?
How does the Tube cross-section change with x?
Does the newest unified policy realize the cumulative Tube?
```

## 51. What JIT does not claim

- not a certified safe Tube;
- not a viability kernel;
- not a formal reachability set;
- not proof of the existential physical jump limit;
- not a two-policy deployment system;
- not evidence that raw snapshot count equals state-space volume.

# Part XV — Next scientific decision after Tube reconstruction

## 52. If Tube geometry is still sparse/narrow

Priority should be acquisition diversity:

- more distinct physical parent cells;
- more x-slice coverage;
- acquisition designed to enter unoccupied cells;
- candidate deduplication before expensive labeling if implemented prospectively.

## 53. If Tube geometry is broad but pi realization collapses

Then representation/control becomes the stronger question.

Potential future methods:

- latent behavior mode;
ning- goal-conditioned policy;
- mixture/distillation during training but one Actor at runtime;
- policy archive for discovery only;
- explicit regularization of coverage.

These are future questions, not current mainline changes.

## 54. If expansion saturates

Possible stopping evidence:

- negligible new root cells;
- no new x-slice extension;
- stable cross-section bounds;
- repeated frontier acquisition falls into occupied cells;
- resource budget.

Only after a stopping decision and final policy freeze should final TEST/JCE/JEL be opened.
